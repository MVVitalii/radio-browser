# Radio Browser — ночной эфир

Интернет-радио на React + TypeScript. Портфолио-проект: показывает Redux Toolkit и работу с чужим REST API через `fetch`. Своего бэкенда нет, станции берутся из открытого [Radio Browser API](https://www.radio-browser.info/).

## Возможности

**Поиск**
- По названию, с задержкой ввода; устаревшие запросы отменяются.
- Фильтры: страна, жанр, сортировка (популярность, рейтинг, качество, название), «только HTTPS».
- Клик по жанру на карточке сразу ищет по этому жанру.
- «Загрузить ещё» — постраничная догрузка результатов.
- Отдельно оформлены загрузка (скелетоны), ошибка с повтором, пустой результат и стартовый экран.

**Плеер**
- Станция играет, пока ищешь другую. Внизу панель «сейчас играет»: пауза, громкость, выключение звука, избранное, «поделиться».
- После паузы живой эфир продолжается с текущего момента, а не с отставанием.
- Громкость и последняя станция переживают перезагрузку.
- Media Session API: станция на экране блокировки и в системном медиа-виджете, управление кнопками гарнитуры.
- Горячие клавиши: `Пробел` — пауза, `M` — звук, `/` — поиск.
- «Мне повезёт» — случайная станция из ста популярных с учётом фильтров.
- Ссылка на станцию `?station=<id>`: получатель увидит её в плеере.

**Избранное и история**
- Избранное в `localStorage`, не сбрасывается при поиске; фильтр по тексту и сортировка.
- «Недавние» — последние 10 прослушанных станций.

**Интерфейс** — адаптивный (от 360 px), доступный с клавиатуры и для скринридеров, уважает «уменьшить движение».

## Стек

React 19 · TypeScript (strict) · Redux Toolkit 2 · Tailwind CSS 4 · Vite · Vitest + Testing Library

## Архитектура

```
src/
  api/radioBrowser.ts        fetch-клиент: зеркала, нормализация ответа, ApiError
  app/
    store.ts                 configureStore, четыре слайса
    persistence.ts           listener middleware: localStorage и адресная строка
    createAppAsyncThunk.ts   типизированный createAsyncThunk
    hooks.ts                 useAppDispatch / useAppSelector
  features/
    stations/                поиск, фильтры, «загрузить ещё»
    player/                  плеер, Media Session, ссылки, «мне повезёт»
    favorites/               избранное и мемоизированные селекторы
    recent/                  недавно прослушанные
  components/                презентационные компоненты
  hooks/                     горячие клавиши, всплывающие сообщения
```

| Слайс | Состояние |
|---|---|
| `stations` | фильтры, параметры активного поиска, результаты, статус, `hasMore`, догрузка, списки стран и жанров |
| `player` | текущая станция, пауза, громкость, без звука |
| `favorites` | избранные станции, сортировка |
| `recent` | последние прослушанные станции |

### Решения, на которые стоит обратить внимание

- **Только сериализуемое в Redux.** `HTMLAudioElement` живёт в `useRef` панели плеера и синхронизируется со стором эффектами. Панель смонтирована в корне, поэтому поиск не прерывает звук.
- **Гонки запросов закрыты дважды.** Предыдущий поиск отменяется через `abort()` (signal уходит в `fetch`), а редьюсер принимает ответ только с актуальным `requestId`. Для «загрузить ещё» — свой `requestId`, поэтому догрузка от старого поиска не смешается с новым.
- **`condition` в thunk'ах.** Списки стран и жанров грузятся ровно один раз, «загрузить ещё» не стартует повторно и без продолжения.
- **Слайсы реагируют на чужие экшены.** `recent` слушает `player/playStation` через `extraReducers` — плеер ничего не знает об истории.
- **Побочные эффекты — в listener middleware.** Запись в `localStorage` и обновление адресной строки вынесены из редьюсеров. Сохранение громкости «дебаунсится» через `cancelActiveListeners` + `delay`: ползунок шлёт десятки экшенов в секунду, а пишется только последний.
- **Мемоизированные селекторы.** `selectVisibleFavorites` (`createSelector`) фильтрует и сортирует избранное и возвращает тот же массив, пока не изменились входные данные. `selectFavoriteIds` даёт `Set` для проверки «в избранном ли» за O(1) в каждой карточке.
- **Устойчивость.** Перебор зеркал API, понятные сообщения об ошибках, битые данные в `localStorage` отбрасываются, запрет автозапуска браузером не считается ошибкой потока.
- **http-потоки.** На https-сайте браузер блокирует незащищённые потоки, поэтому там по умолчанию включён фильтр «только HTTPS», а у http-станций есть пометка.

npm run build
